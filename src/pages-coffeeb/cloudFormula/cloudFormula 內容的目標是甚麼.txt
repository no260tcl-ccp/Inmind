
在來源檔案 `cloudFormula.pdf` 中，此程式碼的核心目標是**建立一個「雲端/熱門配方大廳」頁面**。它提供使用者一個線上的配方庫，讓使用者可以瀏覽官方或他人分享的優秀咖啡沖煮參數，並能**一鍵將這些配方透過藍牙同步至實體咖啡機進行自動沖煮**。

以下為其具體實現的四大核心子目標與運作邏輯：

### 1. 雲端配方的獲取與雙分類展示
* **動態拉取資料**：在頁面初始化（`onMounted`）時，呼叫後端 API `/repice/repice/list`，動態獲取雲端伺服器上的配方數據。
* **熱門與精密分流**：將獲取到的配方依據類型進行分類，分別呈現在兩個滑動輪播區塊（`swiper`）中：
  * **熱門配方 (Hot List)**：展示使用者喜愛的高人氣配方卡片，包含咖啡粉量、粉水比、研磨檔位等簡要資訊。
  * **精密萃取 (Extract List)**：展示結構更細緻、具備多段階段注水的專業配方清單。

### 2. 完美的藍牙協議發送 (配置設備)
* 當使用者決定採用某個雲端配方並點擊「配置」時，頁面會觸發 `sendFormula` 流程。
* 程式會將該配方的**核心參數**（如：配方名稱、粉量、粉水比、磨豆狀態、研磨檔位、馬達轉速，以及**最多 5 段的詳細注水水量、流速、水溫與悶蒸時間**）打包成二進位 Byte 陣列。
* 最終呼叫 `coffeeMachineProtocol.sendRecipeData` 經由藍牙發送給實體咖啡機，完成硬體端的配方寫入。

### 3. 遠端啟動沖煮 (Brewing Control)
* 當配方發送（配置）成功後，頁面會跳出確認彈窗並呼叫 `start` 函數。
* 系統會確認設備目前是否空閒，接著透過藍牙發送「開始沖煮」的指令（`sendBrewMode`）。
* 成功啟動後，App 會**自動跳轉至沖煮動畫頁面 (`/pages-coffeeb/brew/brew`)**，讓使用者在手機上即時觀看整杯咖啡的製作進度。

### 4. 配方詳情二次檢視
* 當使用者對某個推薦配方感興趣時，點擊卡片（`itemClick`）會將該配方的 JSON 參數進行序列化與 URL 編碼。
* 接著透過路由引導跳轉至**沖泡詳情頁 (`formulaDetail`)**，供使用者查看更完整的沖煮曲線與各階段參數細節。

告訴我 來源中 cloudFormula 內容的程式碼如何運作 ?
===================================================
在來源檔案 **`cloudFormula.pdf`** 中，這段程式碼的核心任務是打造一個「雲端配方庫/熱門推薦大廳」。它透過後端 API 獲取雲端推薦資料，並與實體咖啡機的藍牙通訊協議深度綁定。

以下為您詳細剖析這套程式碼的五大核心運作模組與執行邏輯：

---

### 1. 雲端配方拉取與自動分類 (Data Fetching & Categorization)
當此頁面載入（生命週期 `onMounted`）時，系統會自動啟動資料初始化：
* **請求雲端 API**：觸發 `queryList(1, 100)` 方法，透過 `httpGet` 向伺服器端 `/repice/repice/list` 發送非同步請求，拉取目前可用的雲端配方。
* **資料解析與背景指派**：在 `run().then` 的回呼中，系統會利用 `JSON.parse` 將配方的 `configJson` 字串還原為 JSON 物件。同時，它會隨機從 `formulaBgList` 陣列中為每個配方抽取對應的莫蘭迪色系背景圖片 (`bgUrl`) 與文字顏色 (`textColor`)。
* **配方智能分流**：
  * **熱門配方 (`hotList`)**：若配方的 `type === 1`，則直接推入 `hotList` 響應式陣列，展示於畫面頂部。
  * **精密萃取 (`dataList`)**：其他類型的配方會被打包，以 **4 筆配方為一組** 整理進二維陣列 `dataList` 中，以多列清單的形式呈現。

---

### 2. 多重輪播元件與互動 (Swiper Interaction)
為了提供極佳的手滑體驗，畫面上配置了兩個主要的輪播組件（`<swiper>`）：
* **熱門配方輪播**：綁定 `hotList` 陣列，使用者左右滑動時，觸發 `changeHotSwiper` 函式，即時更新頂部右上角的目前頁碼指示器（如 `1/10`）。
* **精密萃取輪播**：綁定 `dataList` 陣列，滑動時會觸發 `changeSwiper` 以更新對應的 `currentIndex`。卡片右下角會顯示精美的大型透明「段數數字」，顯示該推薦配方包含了多少個注水段落。

---

### 3. 跳轉詳情與參數加密傳遞 (Page Navigation)
當使用者點擊任何一張配方卡片時，會觸發 `itemClick(item, index)` 函式：
* **參數編碼打包**：調用 `encodedParams(item)` 函數，將該配方的配置（如粉量、粉水比、段數、水溫等）與使用者 ID、配方 ID 等融合成一個完整的 JSON 物件。
* **安全 URL 傳遞**：利用 `JSON.stringify` 將物件字串化，再以 **`encodeURIComponent` 進行安全字元編碼**（防止 JSON 特殊字元破壞 URL 結構）。
* **路由跳轉**：最終，呼叫小程式原生路由 `uni.navigateTo`，將加密後的整串配方資料以 `data` 參數傳遞，跳轉至配方詳情頁面 `/pages-coffeeb/formulaDetail/formulaDetail`。

---

### 4. 核心藍牙協議封裝與發送 (0x06 Protocol Transmit)
當使用者選定心儀的配方並點擊「配置」按鈕時，會呼叫 `sendFormula` 進入設備參數寫入流程：
* **失敗重試機制**：為了防止藍牙訊號干擾，系統使用 `retry(() => send(data), 3, 500)` 包裝發送函數。一旦命令發送失敗，系統會在背景**自動每隔 0.5 秒重試一次，最多重試 3 次**。
* **資料拆解與 Bytes 組裝 (`send` 函數)**：
  1. **配方 ID 拆解**：將 32 位的整數配方 ID 透過位移（`>>`）與按位與（`& 0xff`）運算，**精準拆解為 4 個獨立的 8 位元位元組 (Bytes)**，填入資料陣列的最前端。
  2. **基礎參數對位**：將粉水比（`proportion / 2`）、粉量（`legumes`）、研磨狀態（`grind ? 1 : 0`）、研磨檔位（`gear`）、轉速（`speed`）與注水總段數對位塞入。
  3. **注水階段補零防呆**：利用一個 `0` 到 `4` 的迴圈，將各階段的「水量、流速、水溫、類型、時間」推入。如果該配方**不足 5 段，剩餘的欄位會自動以 `` 進行零填充對齊**，確保數據長度絕對安全、一致。
  4. **名稱轉碼與填充**：透過 `stringToUTF8Array` 將配方名稱轉為 UTF-8 陣列。配方名稱最大長度限制為 40 位元組，不足 40 位元組的部分一樣會**自動補 0 填滿**。
  5. **發送封包**：最終呼叫 `coffeeMachineProtocol.sendRecipeData(data)`，透過底層 Web BLE 特徵值將整串寫入命令發送給實體咖啡機。

---

### 5. 開始沖煮與頁面同步 (Start Brewing)
當配方順利配置完畢，且機器成功響應返回確認碼 `'dd'` 後，系統會自動拉起控制底面板 `showSheet(formulaData)` 並提供「開始」沖煮按鈕：
* **狀態防呆攔截**：點擊開始時，系統首先檢查機器目前的運轉狀態 `runStatus`；若非 `0`（即機器正處於研磨、注水等工作狀態），會立刻阻斷操作並發出警告，防止硬體衝突。
* **啟動指令發送**：確認機器空閒後，系統會打包長度為 9 位元組的沖煮狀態陣列（包含狀態碼 `1`、研磨與否、拆解後的 4 位元組配方 ID、段數等資訊）。
* **跳轉至沖煮監控**：同樣執行 3 次重試，發送 `sendBrewMode` 給機器。發送成功後，將配方 ID 儲存在本地快取 `uni.setStorageSync('id', item.id)` 中，並**自動跳轉至對應的動畫沖煮頁面 `/pages-coffeeb/brew/brew?id=`**，讓使用者開始實時監控沖煮進度。
